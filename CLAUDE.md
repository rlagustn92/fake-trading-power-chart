# FAKE TRADING POWER CHART

Tauri 2 Windows app for paper trading on replayed charts. It is a clone of `POWER CHART AND BACKTEST` (charts with lightweight-charts v5.2.1 + DCA backtest), made on 2026-10-30, with a paper-trading layer added. Motto: easy and simple, big fonts; powerful but light and fast. The user writes in Korean, does not code, and wants replies and UI text in Korean.

- **Start here: [STATUS.md](STATUS.md).** It lists what is done, what is unverified, and what is pending. Check today's date against its date first, and update it at the end of each work round.

- Usage, shortcuts and dev commands: [README.md](README.md). Original spec: [SPEC.md](SPEC.md). Yearly maintenance (CPI dates, FOMC): [MAINTENANCE.md](MAINTENANCE.md).

## Paper trading code
- New features go in `web/trade/` only: `engine.js` (pure fill rules, tested), `orderlines.js` (draggable price lines on a cell), `history.js` (Binance 1m backfill), `panel.js` (the 💰 panel), `journal.js` (trade cards in the panel and the 📒 journal overlay with curve, table, filters, and click-to-review).
- Trade log colors: only P&L is colored (red profit, blue loss, like the candles). Direction is uncolored ▲ 롱 / ▼ 숏. The user chose this layout (mockups A + C) on 2026-10-30.
- Compare overlay "가격 그대로" (0.10.0, a chart feature, so it lives in `ui/cell.js` and the 보기 menu in `ui/toolbar.js`): `cc.compare_mode = "price"` puts the first compare symbol on the left price scale. Its range comes from `autoscaleInfoProvider` (`cmpAlign`, set in `alignLeft`), so the two lines meet at the last bar where both symbols have a bar (`c.fresh`). The slope k comes from per-bar log returns (`leverageOf`), not price levels: SOXL vs SOXX gave 3.0 over 1 month to 3 years, while a level fit drifted between 1.5 and 3.4 because of leveraged decay. The legend shows prices in both modes. Hovering in "가격 그대로" adds axis labels with that day's actual prices (`paintHoverPrices`: price lines with `lineVisible: false`). The user chose (0.11.0) to keep the 3× alignment and add these labels: the points are real prices, and the alignment only places the left axis. Compare symbols are now caught up on every draw (`data.ensure`, which skips if called again within 10 minutes) and redrawn on new bars. Before this, a compare symbol that wasn't on the watchlist stayed days behind.
- 30m timeframe (0.12.0): `TF_SEC` order is the toolbar order and the Alt+number order, so Alt+4 is now 30m. Binance and Hyperliquid fetch native 30m bars (`TF` maps in `sources/`). Stocks build 30m from 5m (`BASE_TF` in `core/intraday.js`). Hard-coded timeframe lists that had to change: `symbols.js` tfs, `picker.js` TF_KEYS, `indpanel.js`, `settings.js` TF_ORDER, `cell.js` show, `main.js` prefetch and Alt regex, and `history.js` BACKFILL_TFS, CHART_TFS and TF_KO.
- Binance rate budget (0.12.1, the user asked for "50% of the limit"): `BN.klines` counts request weight over a sliding minute. Weight is 5 for 500–1000 bars and 10 for 1001–1500. Bulk downloads (`bulk: true`) stop at 1200/min and all requests together at 1600/min. A 429 pauses every Binance request for 1 minute, a 418 for 5 minutes. `history.spanPlan` splits the range into 1000-bar windows and runs 3 at a time; it's used by `backfill` and `backfillChart`. Windows can be planned ahead because perps trade 24h. `listedAt` asks for the first bar (`startTime=0`, limit 1) and caches it as meta `id|tf|first`, so progress and "listed" are exact. `fetchOlder`, `ensureMinutes` and `fillHoles` still page one request at a time. Only Binance was sped up, and NEXT_START_HERE.md has a table explaining why. Alpaca already uses 150 of its free 200 requests a minute. Yahoo gives only fixed ranges. Toss shares its token and quota with Market Board, so it stays at about a third of its limit.
- 0.13.0:
  - Split changes call `grid.resize()`, which keeps existing cells; only `setLayout` and `deleteLayout` still rebuild all cells with `build()`. New cells join the running replay through `env.joinReplay` → `replay.join` → `cell.joinReplay`, which sets `resumeT` and loads with keepReplay. `replay.checkCells` ends the replay only when the master cell is gone.
  - Actions that would end a session call `env.guard` / replay `confirmEnd` → `guardTrading` in main.js. It shows a confirm dialog only while holding a position or a pending line (`trading.stake`; the name `session` was already taken by a getter that returns the raw `ses`).
  - Up/down colors live in `core/colors.js` (`upColor()`, `downColor()`, `tpColor()`, and `setCandleStyle` from `cfg.chart.candle_style`, "kr" or "us"). Read them at draw time and never cache them in module constants.
  - Indicator swatches: `SWATCHES` (16). Drawing swatches: `DRAW_COLORS` (16). Custom colors: `colorPick` in ui/dom.js.
- 0.14.0: SMA and EMA take a `src` param (`calc.SOURCES` / `calc.source`, matching TradingView sources). Indicator params now include `type: "select"` (with `options`), drawn by indpanel. Alerts pass `src` through. The new indicator `dualma` draws SMA (or EMA) of close, high and low, a band fill, and an optional 200 MA. The user asked for it after a YouTube video: "듀얼 이동평균", a band from the 20 MA on high and low.
- 0.14.1: the replay's ⏭ 한 칸 and the → key call `replay.stepBar()`. It walks `replayNextEnd` up to `cell.replayBarEnd` (the end of the master's current bar), draws once, and the panel still judges every 1m bar in between. Shift+→ is `replay.step()` (1 minute). ▶ play still steps by minute.
- 0.16.0: the indicator `mtfma` ("멀티 이평") draws 15m, 1h, 4h, 1D and 1W MAs in one indicator. Defaults are 20, 20, 20 and 200, and the 1W row starts off. Each row has its own on/off and length (`on_<tf>`, `len_<tf>`, `group` boxes in indpanel), plus one SMA/EMA `kind`. Rows reuse the old "기준 봉" path (`ctx.htf` + `mapHtf`, TradingView-style steps with no lookahead). `tfMode(want, chartTf)` returns same/htf/lower; a "lower" row or `tf` param is hidden for every MA/band indicator. Before this, such a line silently became the chart-timeframe MA. Extras: axis name tags (`title` + `lastValueVisible`), legend distance % (`more`) and 정배열/역배열 (`maOrder`, ordered by tf seconds × length). Legend items can now include `br` (new row). The user put stability and no maintenance above everything else for this feature.
  - `shape` (0.17.0, the user's choice): "smooth" (default) or "step". Smooth uses `mapHtfLive`: per lower bar, the closed HTF closes before the bucket plus that bar's close (= what the HTF chart showed at that moment). It never uses the stored, already-finished bucket, so replay has no lookahead, and it equals the step value at the bucket's last bar. 1D/1W rows ignore extended-hours bars on intraday charts. Other `tf` indicators stay step.
  - `fit` (default on, the user's choice): mtfma lines use `autoscaleInfoProvider: () => null`, so far lines (1D 200) don't squash the candles. Off-screen lines and their axis tags are then hidden; lightweight-charts doesn't pin labels to the edge.
  - Higher-timeframe cache (`loadHtf` in cell.js): a load made during a replay is never `live`, and `to` is the end of the last loaded bar. Before this, a replay-time load was kept as live, so after a replay restart or end the line stayed at the old replay value.
  - `mapHtf` in replay: the last bar uses its HTF value once `key(endT) >= htf.t + span` (`htfOpt` passes `ctx.replayEnd` and `TF_SEC`). Before this, it lagged one step at exact boundaries such as "⏭ 한 칸" landing on 15:00.
  - `cutTo` no longer forces at least one bar. A follower cell with no bar before the replay time shows a message instead of the first future bar.
  - Brush (0.16.0): with the brush tool on, the drawbar shows colors and widths 1–5 (`brushStyle(cfg)`, saved as `cfg.chart.brush`). Selected brush strokes also offer 1–5 px; other drawings keep 1–3.
  - Symbol picker: rows are selected only on real pointer movement (`hoverRow` compares screenX/Y with the last seen position, reset in `open()`). Before this, `pointerenter` fired on rows re-rendered under a still mouse, so typing QQQ + Enter opened QQQB.
  - The indicator panel keeps its scroll position across re-renders. `open()` resets it, and a new or opened indicator scrolls into view.
- Old versions for downgrades: from 0.15.0, GitHub Releases keeps every version's EXE, so don't make versioned copies in `release\` any more (the user decided this on 2026-11-03). The older copies (`release\FAKE TRADING POWER CHART <ver>.exe`, 0.12.1 to 0.14.1) stay because they aren't on GitHub. The desktop shortcut points to the unversioned latest EXE.
- Hooks added to original files are small and commented: `ui/cell.js` (1-minute replay stepping with partial bars, keep replay across timeframe changes, `onMain`/`onReplayStart` hooks, `setTradeMarkers`), `ui/replay.js` (🎲 random start, `onBegin`/`onStep`/`onStop`), `main.js`, `ui/toolbar.js`, `index.html`, `styles.css`.
- In split view, a replay always moves every cell to the same time (0.8.1), whatever the sync setting, because a cell showing "now" would reveal the future. Trading happens in the cell where the replay started (`master`). The other cells keep following the replay time even if their symbol changes (`replay.follows` → `cell.load`). Before a cell loads a timeframe mid-replay, `env.beforeReplayLoad` (main.js) downloads any data that is missing, and for Binance it also reaches back to that time. Starting a replay also prefetches the symbol's other timeframes in the background (`prefetchTfs`, 0.8.2). It shows a toast and does not ask; `prepping` stops the same data from being downloaded twice.
- Gap fills (0.16.0, the user's choice): if a bar opens past a resting take-profit or limit entry, it fills at the line price mid-session. It fills at the open only on the first bar after a break (`b.brk` from `E.isBreak`: more than 30 minutes since the previous bar ended, or a daily/weekly bar of a non-perp). Stops, liquidations and breakout entries still fill at the open on any gap. Live mode marks a break when the price was still for over 30 minutes and then moves on a new bar.
- Fills are judged on the symbol's 1-minute bars, not the cell's timeframe. If the store has no 1-minute bars at the replay time (for example Alpaca stocks older than 12 months), the panel falls back to the cell's bars instead of waiting for later 1-minute data.
- Binance perps keep only 4,500 bars per timeframe at first. Scrolling a chart to the left edge fetches older bars (`history.fetchOlder` via `env.fetchOlder` in `cell.loadMore`). Starting a replay fetches 1-minute bars around that time first (`panel.prepare` via replay `onPrepare`), and `moreM1` fetches 3 more days near the end. This leaves separate old blocks in the store, so `coverage` and `backfill` count only the block that runs up to now (`blockStart`). It also means the 1m list read for a replay can jump from the old block straight to recent bars. Before 0.11.1 that stopped fills after day 4, froze the panel's current price, and made the chart step whole bars. Now, for perps, a 1m gap over 30 minutes is a hole. The chart cell stands still and fills it (`cell.fillReplayHole` → `env.fillMinutes`), and the panel re-reads it (`panel.fillHole`). `history.ensureMinutes` runs one fetch per symbol at a time. If the exchange has no bars there either, the replay passes the hole bar by bar (`replay.holeDone`). The panel's `cur()` uses the 1m close only when it is within 30 minutes of the replay time; otherwise it uses the cell's last bar.
- Chart bars in 2-year steps (0.9.0): the 💰 panel's "차트 봉" row has 📥 2년치 받기 (`history.backfillChart`). It fetches 5m, 15m, 1h and 4h back to 2, 4, 6… years before now (`nextYears`), starting from each timeframe's oldest stored bar. For Korean stocks with Toss it calls `backfillToss` with the same step. The user chose 2-year steps over "all the way back" because listing dates vary so much. Reaching the listing date stores the meta `id|tf|listed`, so the button stops. Pulling 5m or 15m back shows a one-time toast with the same button (`pullTip` in main.js).
- Leverage uses isolated margin with Hyperliquid-style liquidation (maintenance = half the initial margin at the max leverage, `cfg.trade.max_lev`). The order input is the margin, not the position size. Scaling in averages the entry; partial closes realize P&L immediately, and one trade record is written when the position is fully closed.
- Take-profit/stop-loss lines start switched off by default (`tpOn`/`slOn`, setting `tpsl_on`); only switched-on lines fill (`armed()` in panel.js). Right-click a line to toggle it. While dragging, the pointer y is clamped to the pane and the price scale stays frozen, and lines far from the bar range are left out of autoscale and pinned at the pane edge. This stops the runaway-drag bug from 0.4.0, which squashed the chart and threw "Value is null".
- Pending entry lines (`pend` in panel.js): the type follows the line's side of the current price (limit or breakout stop, `engine.pendingType`). On the bar where one fills, only stop-loss and liquidation are checked. Risk sizing (`size_mode: "risk"`) sizes the position so hitting the stop loses `risk_pct`% of cash, including slippage and fees (`engine.sizeForRisk`).
- Real-time paper trading (`ses.live` in panel.js, 0.7.0) polls the cell's last bar every 0.5 s. Each tick it builds one bar from the move since the last check and runs the same `judge()` as replay. Changing the timeframe resets that baseline, so the new bar's older range can't fill orders. Changing the symbol ends the session at the last seen price. An open live position is saved to `trades.json` as `livePos` every 5 s; on the next start it is closed at the last seen price (`settleOrphan`).
- Toss 1m backfill for Korean stocks (`history.backfillToss`) stores 1m, 5m and 1h bars older than the Yahoo data already stored, regular session only, with `adjusted=false`. That parameter is allowlisted in `toss.rs` and is read-only. Toss depth was checked on 2026-10-30: Samsung 1m goes back to 2022-11-23. It shares the Toss token and quota with Market Board. The dev server has no Toss, so check it in the EXE.
- When testing on the dev server, back up `tools/dev-data/trades.json` and `config.json` first and restore them after: the user tries the app on the same dev server, so test trades would mix into their journal.

## Working rules
- **Explain first, fix when told** (the user's rule, 2026-11-01): for a problem report or a "확인해 봐", explain the cause, the planned fix and its side effects in plain Korean, and wait. "고쳐줘", "만들어" or "넣어" means go ahead. Fills must match real exchanges as closely as possible ("실제와 같은 게 중요해"). State any difference before changing replay, fills or liquidation.
- `web/` is plain ES modules with no bundler. Dev server: `python tools/devserver.py 5280`. Tests: http://localhost:5280/tests/test.html — all must pass (132 on 2026-11-04). They also import every module, which catches syntax errors that would give the EXE a black screen. Add new modules to the `MODULES` list there.
- Versions: follow [CHANGELOG.md](CHANGELOG.md). Bump `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml` and the root package in `src-tauri/Cargo.lock`, add an entry. Patch for fixes, minor for features.
- **Source lives in a public GitHub repo (since 2026-11-03, 0.15.0): https://github.com/rlagustn92/fake-trading-power-chart.** The user wants only the EXE and the `%APPDATA%` data on their PCs. This setup was copied from the original app (its 1.4.0), with only the names changed.
  - Release = version bump + CHANGELOG + push to `main`. Don't push tags by hand. [.github/workflows/build.yml](.github/workflows/build.yml) sees a version with no Release yet, builds the EXE on GitHub's Windows runner, then creates the tag `v<version>` and the Release with `FAKE-TRADING-POWER-CHART.exe`. Pushes that don't bump the version skip the build.
  - Build speed: tauri-cli comes prebuilt from npm, pinned to `@tauri-apps/cli@2.12.4` (bump it together with the tauri crates). Builds always run on `main`, so the Rust cache (`shared-key: exe`) is reused; tag builds could not share caches. A `keepalive` job every 5 days restores the cache so GitHub's 7-day eviction doesn't delete it. To warm the cache or test a build without releasing, use Actions → "EXE 만들기" → Run workflow with `force`.
  - Since 0.15.0 the app updates itself: it checks GitHub Releases at start and every 12 hours, then downloads, verifies and swaps the EXE, and relaunches. The code is in `src-tauri/src/update.rs` and `web/ui/update.js`. The Release body is the CHANGELOG section for that version, and the app shows it, so write CHANGELOG entries for the user.
  - Updater safety: the repo is a constant in `update.rs`, and JS passes only a version string. The EXE is used only if its SHA-256 and size match the GitHub asset `digest`. Hosts are limited to `ALLOWED_HOSTS` in `update.rs`. These are Rust-only requests, so they are not in `capabilities/default.json`. The dev server only imitates `update_check`.
  - Manual fallback: close the app and replace the EXE with the Release download; data, trades and keys stay.
  - Public repo: never commit keys, logs, market data (`*.db`), backups, trade records, or personal names or paths. `.gitignore` covers the files (`release/`, `*.exe`, `*.zip`, `*.db*`, `*.log`, `tools/dev-data/`).
  - Commits: author `rlagustn92 <73482918+rlagustn92@users.noreply.github.com>`, set in the repo config only. In PowerShell, write Korean commit messages to a file and use `git commit -F`.
